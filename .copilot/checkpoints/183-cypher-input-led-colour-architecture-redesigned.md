# Checkpoint 183 — Cypher-Input LED Colour Architecture Redesigned (RGB, Local, Off `plain-bits`)

**Date:** 2026-08-14
**Session work:** Reworked the Cypher-Input Board's LED indicator circuit from the ground up,
following user review of `Board_Layout.md §1`. The original design piggybacked 2 spare
`plain-bits` positions per variant for `YELLOW_DRIVE_N`/`GREEN_DRIVE_N`, generated by the ENC
module's CPLD. The new design moves colour selection entirely onto Cypher-Input itself (never via
the ENC module or `plain-bits`), makes it software-configurable via the existing I2C GPIO expander
(U4), and adds real-time Shift-triggered colour switching via a small local hardware mux - see
DEC-087 for full detail.

## Key architecture decisions this session (see DEC-087 for full detail)

| Decision | Detail |
| --- | --- |
| `plain-bits` freed for keyswitch-only use | All 64 `PB[]` positions are now reserved exclusively for cipher-path keyswitch inputs on every variant - no LED signals share this bus, on any variant, leaving headroom for a future all-64-lines variant. |
| Colour generated locally, never via the ENC module | LED colour selection is generated entirely on the Cypher-Input board itself (never the ENC module CPLD or its `plain-bits`/`cypher-bits` connectors), since the LED bank and its drive electronics are physically local to the carrier board. |
| Software-configurable RGB via U4 (PCA9534A) | Colour is defined by writing 3-bit RGB codes to U4's GPIO, not CPLD firmware. 64-Char Extended (only variant with a Shift key) uses two codes ("Colour A"/"Colour B", 6 GPIO); Classic/10-Numeric use one fixed-but-configurable code (3 GPIO), since they have no Shift key to switch on. |
| Real-time Shift switching via local hardware mux | Extended variant only: U9 (`74HC157PW-Q100,118`, same part already used as the Cypher Board's own keyboard-source mux U4/U5) picks between Colour A/B in real time, selected by a local, hardware-only `SHIFT_ACTIVE_N` signal - a diode-OR (D9, `BAT54C`) of both Shift key switch nodes (tapped in parallel with their plain-bits connection) pulled up via R9. Deliberately cross-wired (Colour B → mux "A" inputs, Colour A → mux "B" inputs) so `SHIFT_ACTIVE_N`'s natural active-low polarity drives the mux Select pin directly, with no inverter needed. |
| Brightness moves to the LED bank's termination | RV1/555 (U1) PWM output no longer feeds the ENC module's `GCLK0` pin - it now gates U8 (`BSS138`), a shared low-side switch common to every LED's cathode return, downstream of all colour selection. One physical dial (on Cypher-Input only) dims every LED on both this board and the future Cypher-Output board. |
| Broadcast moved from JTAG pair to left connector pair | `RED_DRIVE_N`/`GREEN_DRIVE_N`/`BLUE_DRIVE_N` and `BRIGHTNESS_PWM_EN` are now broadcast to whichever HID board is adjacent via `J4`/`J6` (left pair), not `J5`/`J7` (JTAG chain-through pair). `GREEN_PWM_N`/`YELLOW_PWM_N` (previously J5/J7 pins 30/32) are retired system-wide - updated in both `Cypher-Input/Board_Layout.md` and the canonical template owner, `Cypher/Board_Layout.md §4`. |
| LED part becomes an explicit placeholder | The previous Kingbright APFA2507Y2G2C-C2 bicolour part is retired - BOM rows across all 3 variant files now show `TBD`/placeholder pending the user's own footprint-compatibility check against the Cherry MX2A-71NB keyswitch cutout. Not sourced by the agent, per the established sourcing-responsibility convention. |

## Verification performed this session

- Confirmed the mux cross-wiring logic (`SHIFT_ACTIVE_N` polarity vs. `74HC157` Select pin
  convention: S=LOW selects A-inputs, S=HIGH selects B-inputs) works with a direct wire by
  assigning Colour B to the mux's A-inputs and Colour A to its B-inputs, avoiding an unnecessary
  inverter stage.
- Confirmed GPIO budget fits within U4's 8 pins on every variant: Extended (8/8: 2 Space/Enter + 6
  colour config), 10-Numeric (5/8: 2 Space/Enter + 3 colour config), Classic (3/8: colour config
  only, 5 spare).
- Checked local component library/datasheets for an existing RGB LED suitable for under-key
  mounting - none found; confirmed with the user this sourcing decision is explicitly deferred to
  them, not the agent, per `component-lookup` directive (no web search) and established project
  convention.
- Propagated the `GREEN_PWM_N`/`YELLOW_PWM_N` retirement to both Cypher-Input's own
  `Board_Layout.md` and the canonical shared-template owner, `Cypher/Board_Layout.md §4`, keeping
  both documents consistent.
- Corrected the `Encoder_Module/Board_Layout.md §1a` `plain-bits` usage note, which referenced the
  now-retired "LED drive outputs on Cypher-Input" example.
